# 固件构建、烧录准备与采集

先确认本轮获准的动作和实际项目目标。用户只要求分析或规划时不构建、不打开串口。只要求构建时不改源码或执行板端动作。串口接收须明确端口、参数、设备和窗口；虽然脚本不发送数据，某些驱动打开串口时仍可能改变 DTR/RTS。

- 工具发现、参数、结果和支持边界见 [运行器使用说明](references/runner.md)。使用 [脚本](scripts/board_runner.py) 执行支持的操作，不自动选第一个构建目标或端口，不从项目文件拼接任意 shell 命令。
- 构建前核对项目和可能运行的构建钩子，确认目标与预期产物。只有本轮成功的命令、新生成或重写的产物和必要日志一致时才报告构建通过。将本轮日志和产物保存到独立运行目录。
- 串口保留原始字节、主机接收时间和块边界。离线回放使用相同证据格式，但不是串口连接或实板结果。无数据、断连、超时、达到字节上限按报告保留，不自动重试。
- 烧录准备只验证本轮归档的 `.bin`、板卡、探针标识和声明的写入范围，输出 STM32CubeProgrammer 命令预览。本技能不执行烧录；烧录授权、真实分区与擦除扇区另行核对。
- 将本轮运行目录、结果、构建目标与固件 SHA-256 交给调试环节。采集到数据不证明功能通过；用户只需要分析历史文件时直接读已有证据。
