# 嵌入式闭环调试

1. 对齐现象、预期、复现步骤与本轮权限。核对工程、板卡、实际构建目标、固件或运行记录；版本对不上的日志只能提供线索。
2. 分清问题层级：物理信号、外设接收、驱动或调度、缓冲区、协议解析、应用行为。先读现有证据，选最少的候选原因。对每个关键假设说明什么结果会支持它、什么结果会排除它。
3. 选能区分候选原因的最小实验。一次改变一个条件，其余配置固定；先定成功、失败、无效及停止条件。可用 `embedded-telemetry-planner` 规划采集，用 `firmware-build-flash-runner` 获取已获准的证据。缺少工具、权限或硬件时给出下一步或使用离线回放，注明证据层级。
4. 保留原始数据和运行标识，先确认实验条件成立，再判断结果。没有新证据时停止重复尝试。发现过流、异常动作或运行对象不明时，停止依赖该设备的操作并记录现场。
5. 仅在用户授权修改时，把依据和最小改动交给 `firmware-dev-executor`。用同一输入和判定标准比较修复前后，补测相邻边界；可按需请 `firmware-quality-reviewer` 独立检查。主机回放、构建、烧录和实板回归各自记结果。

## 本轮交接

记录「现象与复现条件 → 基线及证据 → 假设及反证 → 实验结果 → 下一项动作」。用户只要求排查时直接答复；有授权才修改工程或回写调试记录。串口收到了若干块字节，只证明主机读到了这些块；分帧、物理到达时间和 MCU 回调边界还需要对应的证据。
