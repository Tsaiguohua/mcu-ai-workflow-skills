# 原理图接口分析

生成可审核的硬件接口速查表。AI 负责出初稿，工程师负责核对关键风险。

## 优先输入

- 原理图导出的网表、原理图 PDF 或清晰截图。
- MCU 精确型号和封装。
- 板卡版本。
- 负载类型：继电器、电机、加热、阀、蜂鸣器、LED、传感器、屏幕、通信接口等。
- 如果已有芯片手册引脚复用摘录，一并读取。

优先使用网表；只有 PDF/图片时，要标注 OCR 或视觉识别的不确定性。

## 工作流

1. 识别 MCU 和所有连接网络  
   记录 MCU 脚号、端口名、网络名、连接器件、所在页。

2. 推断软件含义  
   判断 GPIO、UART、SPI、I2C、ADC、PWM、中断输入、复位、启动、调试等功能；标注方向、有效电平、上下拉、默认态和初始化建议。

3. 标出危险点  
   继电器、电机、加热、阀、高压 PWM、电源使能、充电路径、Flash 写擦、启动配置脚都要单独列出。

4. 和手册交叉检查  
   检查复用功能是否存在、ADC 引脚是否支持、I2C 是否需要开漏和上拉、Boot/SWD/JTAG 是否冲突。

5. 输出接口表和待确认问题。


## 审核规则

- 电路没有明确证明时，不要把有效电平写成最终结论。
- 三极管、MOS、光耦、继电器驱动、使能脚都属于极性风险项。
- 原理图器件型号可能填错，不能盲信器件标注。
- 看不清或推断链条不完整时，写 `待人工确认`，不要自信猜测。
- 未经人工核对的接口表不能直接作为固件初始化依据。

## 文章中的经验

- AI 能把几小时的引脚整理压缩到几分钟，但人工核对不能省。
- 标注不清、型号错误、网络命名混乱会直接导致 AI 结论错误。
- AI 介入会倒逼原理图规范化：器件型号要对，网络名要清晰，关键标注不能省。
